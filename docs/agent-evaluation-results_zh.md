# Agent 评测结果：Haiku，2026 年 10 月

本页公布 [Agent 评测矩阵](agent-evaluation_zh.md) 的首批完整结果：20 个场景 × 3 条分析路径 × 3 次，用 `claude-haiku-5-5` 采集了两轮。它衡量 Agent 回答流量分析问题的正确率（证据必须是采集器真实看到的），以及为此付出的成本。

**简要结论：** 带 `wireshark-mcp` skill 的 MCP 通过 120 格中的 87 格（73%），不带 skill 的 MCP 通过 78 格（65%），原生 tshark 加 CLI skill 通过 68 格（57%）。两轮的排序相同。skill 的收益几乎都在安全类场景。CLI 路径 Token 最省。

这是一个小模型的结果，不代表所有模型或客户端都会这样。

## 设置

| 项目 | 值 |
|---|---|
| 模型 | `claude-haiku-5-5`，Claude Code `-p`，默认推理档位 |
| 隔离 | 每格一个全新进程；无用户设置、hooks、其他 MCP 服务器或 skill（`--setting-sources "" --strict-mcp-config --disable-slash-commands --no-session-persistence`） |
| 路径 | `without-skill`：MCP `full` profile。`with-skill`：MCP `full` profile，并可读取复制出的 `wireshark-mcp` skill。`tshark-cli`：只能用 `tshark` 和 `capinfos`，加 `tshark-cli-analysis` skill |
| 引擎 | Linux x86_64 上的 TShark 4.2.2 |
| 预算 | 每格 900 秒，Claude Code 默认轮数上限 |
| 采集器 | [`scripts/agent_eval_harness.py`](../scripts/agent_eval_harness.py)；所有查询都经采集器执行，轨迹不由 Agent 自己写 |
| 完整性 | `check_agent_matrix.py`：两轮都是 180/180 格，`collection_complete: true` |
| 花费 | 每轮 180 格约 1.3 美元 |

第二轮使用修复首轮试跑问题后的采集器。第三轮在提示里定义了五个结论档位，并修正了 T19 抓包中重叠的序号。两轮最后都按最终规则重新评分：T15、T17、T18 在 `unresolved` 之外也接受 `confirmed`（正确确认"文件已变化""输出被截断"的回答是对的），观测规则也放宽到 CLI 路径能得到与 MCP 相同的观测。重新评分是从保存的原始输出重新推导观测，没有重跑模型。记录中的 `source_revision`（`fa55bec…`、`1498087…`）是采集器变基进 3.2 之前的提交，相同的改动已包含在本版本中。

原始门控输出：[第二轮](benchmarks/agent-matrix-2026-10-18-haiku-run2.json)、[第三轮](benchmarks/agent-matrix-2026-10-18-haiku-run3.json)。

## 结果

| 路径 | 第二轮 | 第三轮 | 合计 |
|---|---|---|---|
| with-skill（MCP + skill） | 45/60 | 42/60 | **87/120（73%）** |
| without-skill（MCP） | 38/60 | 40/60 | 78/120（65%） |
| tshark-cli（原生 CLI + CLI skill） | 36/60 | 32/60 | 68/120（57%） |

每条路径每轮 60 格，轮间波动约 ±4 格，所以 with-skill 与 without-skill 的差距（两轮共 9 格）只能算倾向，还不是定论。与 CLI 路径的差距更大，且两轮一致。

## 失败原因

1. **候选类问题的档位校准。** T04、T07 问"是否为候选"，模型通常答 `likely`。这是最常见的失败（三条路径共 29 格），提示里定义档位后也没有改变。
2. **把截断的输出当作证据。** T18 中 MCP 路径常把触及输出预算的调用当作普通证据引用；CLI 路径更常在只能支持 `partial` 时报 `coverage: complete`。
3. **事实格式。** 需要数量时返回了名单（T04 子域名），或把两条凭据数成三条（CLI 路径的 T05）。
4. **未知字段之后的覆盖度。** T16 问 tshark 不认识的字段。CLI 路径 6 次通过 5 次；MCP 路径结论正确，但覆盖度报 `partial`，场景要求 `unknown`（12 格中 11 格如此）。

## 已知局限

- 只有一个模型、两轮。更强的模型可能缩小或扩大 skill 的收益。
- 引擎是 TShark 4.2.2，不是 CLI skill 所记录的 4.6.9 能力目录。
- 部分判断类事实按每个场景一条采集器规则推导。T19 中注入文本在原始 tshark 输出里以十六进制出现，CLI 路径常拿不到"指令只是数据"的观测，因此这一项对 CLI 路径偏低。
- 通过要求结论、事实、证据锚点、覆盖度都正确且没有禁止的说法，部分正确也算失败。
