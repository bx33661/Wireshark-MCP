# Agent Traffic Analysis Evaluation

This suite measures whether an Agent answers packet-analysis questions correctly and preserves evidence boundaries. It evaluates the Wireshark MCP skill against the same tasks without the skill or with direct tshark guidance. It does not rank variants by a single blended score.

## Dataset

`evals/agent-traffic-analysis/scenarios.json` contains 12 tasks across factual queries, security analysis, failure handling, coverage, and troubleshooting. Deterministic captures are generated by `tests/fixtures/generate_pcaps.py`. Synthetic failure scenarios must be run with the failure condition described by the scenario rather than a real capture.

Each variant should run every scenario in a fresh Agent context with the same model, reasoning setting, tool profile, time budget, and capture. Run at least three repetitions before comparing stability. Recommended variants are `without-skill`, `with-skill`, and, when relevant, `tshark-cli`.

Do not expose expected facts, forbidden claims, or scoring rules to the Agent. Record the final answer and actual tool transcript in the structured result format. A proposed command is not evidence that the command ran.

## Result contract

Use `evals/agent-traffic-analysis/result.example.json` as the shape. Facts are machine-checkable observations. `conclusion` is one of `confirmed`, `likely`, `candidate`, `unresolved`, or `no_match`. Evidence anchors contain their type and executed query; frame and stream anchors should also include the observed number. Coverage describes the executed scan.

Efficiency metrics remain separate from correctness. Fewer tool calls, lower elapsed time, peak RSS, or tokens matter only after a run passes correctness, evidence, and coverage checks. Use the [MCP and native tshark comparison](analysis-path-benchmark.md) to collect and compare both execution and Agent-level measurements.

## Scoring

```sh
python scripts/evaluate_agent_traffic.py path/to/results.json
```

The command exits nonzero when a submitted run fails or the suite is incomplete. During development, `--allow-missing` permits scoring a subset. Use `--output report.json` to retain the report.

The scorer checks facts, conclusion calibration, coverage, evidence anchors, forbidden overclaims, and the rule that partial scans cannot support capture-wide absence. Human review is still required for causal support and realistic alternative explanations.

Report per-scenario pass rates and variance across repetitions. Compare efficiency only among passing runs. Preserve model, Skill revision, MCP revision, tshark version, operating system, and commit identifier with published results.
