# Agent traffic-analysis evaluation

The suite separates **skill structure**, **engine execution**, and **Agent behavior**. A valid SKILL.md or passing deterministic test is not evidence that an LLM became more accurate. Do not publish improvement claims without independent runs.

Published runs: [Agent evaluation results](agent-evaluation-results.md) (Haiku, two runs of the full matrix).

## Collect independent runs

Use every scenario in `evals/agent-traffic-analysis/scenarios.json`, with at least three fresh-context repetitions per variant: `without-skill`, `with-skill`, and `tshark-cli`. Keep model/reasoning setting, tool profile, time/output budget, engine/plugins, OS and code/Skill revisions fixed. Capture references are deterministic fixtures generated by `tests/fixtures/generate_pcaps.py`; `synthetic://` cases require the specified injected condition, not an ordinary clean capture.

Give the Agent only its prompt, permitted input and selected skill/tools. Do not reveal expected facts, scoring rules or intended conclusions. Keep raw tool transcripts in a harness-owned trace directory separate from Agent-writable answers. Preserve exact executed arguments, input SHA-256, tool errors, result artifacts and output/scan coverage. Redact secret content before sharing; retained raw sensitive evidence needs appropriate access controls.

Reusable evaluation prompt:

```text
Use the selected packet-analysis workflow to answer the supplied question.
Investigate only the provided input and scope. Record actually executed queries,
observed anchors, scan/output coverage and material limits. Do not invent a
successful run or a follow-up solely to fill a template. Return the answer and
references to the execution records collected by the harness.
```

## Result and trace contracts

`evals/agent-traffic-analysis/result.example.json` is strict JSON with illustrative values, not a measured result. Replace its trace ID/digest with actual harness sidecars. `execution.status=completed` means the **investigation** finished; an investigation can correctly conclude unresolved after a failed tool call. Timeout/error investigations are not eligible passing efficiency samples.

Each trace sidecar has:

- `input_id`: scenario capture identifier, and `input_sha256` for real inputs.
- `calls`: unique `id`, exact `query`, `status` (`completed`, `error`, `timeout`), `coverage` (`complete`, `partial`, `unknown`), `result_file`, `result_sha256`, and `observations`.
- `observations.facts`: values extracted/annotated by the harness from retained results; `frames`/`streams`: actual observed integer anchors. Keep causal annotations under human review rather than inferring truth from a string match.

Every answer evidence item references `call_id` and the same executed `query`. A scenario may list `acceptable_conclusions` when more than one label is correct: T15, T17 and T18 accept `confirmed` as well as `unresolved`, because an answer that directly establishes the limitation (a top-10 view is not all groups, the capture changed, the output was cut short) is confirmed by its evidence. Only items of the scenario's accepted types count toward `min_anchors`; items of other types are allowed as supporting context but are checked against the trace in the same way, so a wrong supporting item still fails the run. A frame/stream `value` must occur in that call's observations. Reported facts must match both expected facts and trace observations. Complete claims require matching call coverage; error evidence must reference an actually failed call. Report and trace JSON are separate: the Agent cannot establish authenticity by inventing a `trace` field in its answer.

```sh
python scripts/evaluate_agent_traffic.py runs.json --trace-dir harness-traces --output evaluation.json
python scripts/compare_agent_traffic.py \
  --variant without-skill=baseline.json --variant with-skill=skill.json \
  --trace-dir variant-traces --output comparison.json
```

For comparison, `variant-traces/<variant>/` holds that variant's sidecars/results. Without `--trace-dir`, each results file uses its sibling `traces/`. All paths referenced inside a trace must resolve within the trace directory, and SHA-256 checks bind the sidecar/result bytes. The evaluator rejects missing/different trace digests, modified results, wrong input IDs, invented anchors, unexecuted queries, missing supporting observations, invalid metrics and execution failures. `--allow-missing` permits a development subset, never fabricates coverage for omitted scenarios.

**Integrity is not authenticity or semantic proof.** A malicious or incorrect collector can create internally consistent false records; hashes do not establish provenance. Use a trusted collector, derive observations from raw outputs and review claims against packets. Forbidden-phrase checks are a coarse regression aid, not a multilingual entailment judge; negation, causal support and realistic alternatives still need review. No fixture-expectation dictionaries may be copied into measured trace observations.

## Metrics and release gates

Report per-scenario accuracy, overclaim/fabricated-anchor rate, unsupported-absence rate, redundant calls, elapsed time, input/output tokens and peak RSS. Separate missing metrics from zero. Compare cost only on passing runs and show distribution/variance across repetitions, not a blended score or one cherry-picked trial.

Before release: validate both skills and all reference links; check cited MCP schemas; review capability-catalog gaps; verify source, client discovery and wheel contents separately; execute representative native commands and timeout/output-limit recovery; score actual independent traces. Keep engine microbenchmarks separate from Agent quality (see [comparison guide](analysis-path-benchmark.md)).

## Repeated comparison matrix

One run per scenario is not a repeated controlled experiment:

```sh
python scripts/check_agent_matrix.py --prepare /absolute/path/to/new-blind-tasks
```

This prepares 180 blind input tasks (20 scenarios × 3 variants × 3 trials); it does not invoke a model or produce scores. Grading facts, conclusions, evidence rules and injection recipes are omitted. Synthetic inputs explicitly require a fixture adapter to instantiate the stated real observations/failures. Do not count uninstantiated placeholders as completed work. Execute each task in a fresh context, not as a batch in one conversation or by toggling skill loading in one context.

Reusable execution prompt, with the selected backend, real input and optional skill, but no expected answer:

```text
Answer the user question in task.json using only the specified offline input.
Use the selected backend and load the selected skill only when one is specified.
Return the conclusion, facts, executed queries, observed anchors, coverage and material limits.
The collector independently records raw outputs, statuses and metrics; do not fabricate collector records.
```

The trusted trace additionally records a unique collector-observed `context_id` and an `experiment` object with fixed `model`, `reasoning_effort`, `engine_version`, `plugin_fingerprint`, `platform`, `source_revision` and `budget`. Include uncommitted source/skill digests in the source revision, not Git HEAD alone; explicitly use `none` for no plugins. `tool_profile` may differ by variant but must stay fixed within a variant. Each answer includes the selected `variant` and integer `trial` (1–3), bound to its trace as before.

```sh
python scripts/check_agent_matrix.py \
  --variant without-skill=baseline.json --variant with-skill=skill.json \
  --variant tshark-cli=cli.json --trace-dir variant-traces --output matrix.json
```

The gate exits 1 for missing/duplicate cells, reused contexts/traces, inconsistent settings, digest mismatches or incomplete investigations. `collection_complete` measures collection consistency/completeness, not answer correctness or demonstrated skill benefit. Keep wrong baseline answers for comparison. Unique IDs/digests are not authentication or causal proof; independently review input scope, reasoning and collector trust.

The comparator adds sample/missing counts, minimum, median, maximum and sample standard deviation for eligible efficiency metrics. One sample has unknown standard deviation, not zero. Missing Token/RSS measurements stay missing.

## Running the matrix with the collector

`scripts/agent_eval_harness.py` is a trusted collector for the matrix. It builds the nine `synthetic://` inputs (failed DoS sub-queries, a 64-byte snaplen, two unsynchronised sensors, a 15-source top-k, an unknown field, a changed capture, a 4 KB output budget, instructions inside a payload and a known frame), writes one blind cell per scenario × variant × trial, and runs every query the Agent makes so the trace is written by the collector, not by the Agent. It does not call a model: you bring the Agent.

```sh
EVAL=/absolute/path/to/new-eval-dir
uv run python scripts/agent_eval_harness.py prepare "$EVAL" \
  --model <model-id> --reasoning-effort <setting> --budget "30 min, 60 tool calls per cell"
```

Each `cells/<scenario>--<variant>--t<n>/` holds `task.json` and `prompt.md`. The prompt tells the Agent to run every query through `agent_eval_harness.py call --cell <cell> {mcp TOOL JSON | mcp-list | cmd tshark|capinfos ... | hash FILE}` and to write `answer.json`. MCP variants use the `full` profile in-process; the CLI variant may only run `tshark` and `capinfos`. Input arguments must name the cell's own inputs. Expected facts live in `.collector/cells.json`, which the Agent must not be able to read.

`drive` runs an Agent command once per unanswered cell, each in a fresh process with the cell as working directory. `{prompt_file}`, `{cell}` and `{harness}` are substituted. With Claude Code, put the isolation flags in a small wrapper so no user settings, hooks, MCP servers or skills leak in, and grant read access only to the copied skills and write access only to the cell's answer (permission paths are absolute, hence the leading `/` before an absolute path; writes are governed by `Edit` rules):

```sh
cat > agent.sh <<'SH'
#!/bin/sh
# agent.sh PROMPT_FILE CELL EVAL_ROOT
exec claude -p "$(cat "$1")" --model <model-id> --output-format json \
  --setting-sources "" --strict-mcp-config --disable-slash-commands --no-session-persistence \
  --tools Bash Read Write \
  --allowedTools "Bash(*agent_eval_harness.py call*)" "Read(/$3/skills/**)" "Edit(/$2/answer.json)"
SH
chmod +x agent.sh
uv run python scripts/agent_eval_harness.py drive "$EVAL" --agent "$PWD/agent.sh {prompt_file} {cell} $EVAL"
```

`reobserve "$EVAL"` re-derives every call's observations from the retained raw results after the collector's rules change, checking each result against its recorded digest; run `finalize` again afterwards. `--only T05_` limits a pass to matching cells; interrupted runs resume because answered cells are skipped. Token usage is read from the Agent's JSON output when it reports `usage`. Then:

```sh
uv run python scripts/agent_eval_harness.py finalize "$EVAL" --output "$EVAL/runs"
uv run python scripts/check_agent_matrix.py --variant without-skill="$EVAL/runs/without-skill.json" \
  --variant with-skill="$EVAL/runs/with-skill.json" --variant tshark-cli="$EVAL/runs/tshark-cli.json" \
  --trace-dir "$EVAL/.collector/traces" --output "$EVAL/matrix.json"
uv run python scripts/compare_agent_traffic.py --variant without-skill="$EVAL/runs/without-skill.json" \
  --variant with-skill="$EVAL/runs/with-skill.json" --variant tshark-cli="$EVAL/runs/tshark-cli.json" \
  --trace-dir "$EVAL/.collector/traces" --output "$EVAL/comparison.json"
```

Limits of this collector, to state next to any published result:

- MCP variants call the server through the collector's command wrapper, not a native MCP client connection, so tool-discovery behaviour of a real client is not measured.
- The prompt lists the fact names (not values) the answer must fill, which is more structure than a real user gives.
- Observations are derived by rules: a value fact counts as observed when a completed call's output shows that value, and each judgment fact has one scenario-specific rule. Input paths are masked first so a file name cannot count as evidence. Review disagreements by hand.
- Isolation depends on the Agent client's permissions; the collector cannot stop an Agent that is allowed to read `.collector/`.
