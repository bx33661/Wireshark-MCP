# 4.0.0 — unreleased

## English

4.0.0 is the first release since 3.1.0. The work prepared as 3.2.0 was never published on its own; it ships here and is listed in the second half of these notes.

### Capture index engine

The 4.0 roadmap items, built ahead of the long-running jobs work. All of it lives in the optional `[index]` extra; the tool count stays at 54 and the `tools/list` payload stays inside the 23,500-byte budget.

- **Capture sets.** `wireshark_index(more_files=...)` builds, queries, exports and reports status for several captures at once. Each capture keeps its own index file; at query time they are attached read-only and stacked with a leading `capture_id` column, and a `captures` table maps ids to paths and SHA-256.
- **Timeline.** `action="timeline"` lists the first and last sighting of hosts, conversations, protocols, DNS names, TLS SNI, HTTP hosts, user agents and JA3/JA4, with exact frame numbers, relative times and UTC time, optionally inside a display-filter window.
- **Diff.** `action="diff"` compares two captures, or two display-filter windows of one capture (`display_filter` vs `compare_filter`), and returns only new and gone items plus per-kind counts.
- **Parquet export.** `action="export"` writes `packets.parquet`, `flows.parquet` and `captures.parquet` under the index directory, optionally filtered.
- **SQL pushdown for `wireshark_aggregate`.** Grouping, distinct counts, numeric metrics and time buckets run inside DuckDB when exactness gates prove the result equals the streaming accumulator; otherwise rows stream as before. `coverage.pushdown` reports which happened.
- **`wireshark_extract_fields` on the index.** A fresh index built by the same tshark answers with byte-identical output; anything that could print differently goes to tshark.
- **10 GB benchmark tier** in `scripts/benchmark_capture_index.py`, which now also times timeline, diff, export and extract_fields. On a 10 GB capture the index answers all five aggregate questions in 0.08–1.1 s; the tshark path fails four of them on the stdout ceiling and needs 581 s for the fifth. At 1 GB the index is 408× faster ([results](../docs/benchmarks/capture-index-2026-10-22.json)).
- Query connections are now in-memory DuckDB sessions with each index attached read-only before external access is disabled and the configuration locked. Index files keep schema version 1, so 3.2 indexes stay valid.

### Also in 4.0.0: evidence-first findings (prepared as 3.2.0)

#### Highlights

- **Unified findings**: every detector returns the same evidence-backed
  `data.findings` shape, with a stable id, a native `tshark` command to
  reproduce it and candidate MITRE ATT&CK techniques.
- **Investigation case files**: `wireshark_case` keeps captures, recorded tool
  results, findings, analyst verdicts and notes in one JSON record, and renders
  the Markdown report only from that record.
- **Optional DuckDB capture index**: `pip install 'wireshark-mcp[index]'` adds
  `wireshark_index`; one tshark pass makes later `wireshark_aggregate` calls
  about 21x faster at 100 MB and 27x at 1 GB, with answers equal to the tshark
  path.
- **Published Agent evaluation**: two Haiku runs of the 180-cell matrix, with
  collector-written traces. MCP with the skill passed 73% of cells, MCP alone
  65%, native tshark 57%; the skill's gain is in security scenarios. See
  [Agent evaluation results](../docs/agent-evaluation-results.md).

#### Added

- Unified findings: every detector returns `data.findings` with a stable
  content-hash `id`, producing `tool`, `category`, native `tshark` `reproduce`
  commands and candidate `mitre_attack` techniques for non-informational
  findings. Beaconing, exfiltration, protocol-anomaly, ARP-spoofing and YARA
  results moved from Markdown or ad hoc JSON to this shape, and
  `wireshark_quick_analysis` renders its anomaly section from the findings it
  returns (`data.report` plus `data.findings`).
- `wireshark_case` keeps investigations as JSON case files under the allowed
  write root: capture SHA-256s, recorded tool results with digest, scope and
  coverage, findings merged by id, analyst verdicts and notes, and a Markdown
  report rendered only from that record. `wireshark://cases/{case_id}` exposes
  the full JSON. See [Findings and cases](../docs/findings-and-cases.md).
- Optional DuckDB capture index (`[index]` extra). `wireshark_index` builds a
  local DuckDB index of a capture in one tshark pass (`action="build"`),
  reports freshness (`status`), drops it (`drop`), and runs one read-only,
  sandboxed `SELECT` over the `packets`, `pkt` and `flows` tables (`query`).
  See [Capture index](../docs/capture-index.md).
- `wireshark_aggregate` uses a fresh index automatically and reports
  `coverage.source` (`"index"` or `"tshark"`). Index columns hold tshark's own
  field text, so indexed answers match the tshark path; filters the index
  cannot reproduce exactly, and fields it does not store, fall back to tshark
  with the reason in `coverage.index_unused`.
- `scripts/benchmark_capture_index.py` and published results for 100 MB and
  1 GB synthetic captures.
- `scripts/agent_eval_harness.py` collects the 180-cell Agent matrix: it builds
  the nine `synthetic://` inputs, writes blind cells, executes every Agent query
  itself so traces are collector-written, drives any command-line Agent once per
  cell and emits runs files for `check_agent_matrix.py`. See
  [Agent evaluation](../docs/agent-evaluation.md#running-the-matrix-with-the-collector).
- [Agent evaluation results](../docs/agent-evaluation-results.md) for two
  Haiku runs, with the gate output in `docs/benchmarks/agent-matrix-2026-10-18-*.json`.

#### Changed

- `wireshark_detect_beaconing`, `wireshark_detect_exfiltration`,
  `wireshark_detect_protocol_anomalies`, `wireshark_detect_arp_spoofing` and
  `wireshark_yara_scan` return the result envelope with `findings`, `summary`,
  `scope` and `coverage` instead of plain text. `wireshark_quick_analysis`
  returns `data.report` instead of a bare string.
- The tool surface is 54 tools (analysis 42, core 34): `wireshark_case`, the
  only tool that keeps state, and `wireshark_index`, which writes only the
  server's own index cache and is annotated non-destructive. The tools/list
  prefix budget is 23,500 bytes.
- Agent scoring counts only the scenario's accepted evidence types toward
  `min_anchors`; evidence of other types is allowed as supporting context and
  is still checked against the trace. Previously any extra supporting item
  failed the run.
- Scenarios may list `acceptable_conclusions`. T15, T17 and T18 accept
  `confirmed` alongside `unresolved`, and T17/T18 accept the coverage of a
  query that settles the limitation; three Haiku rounds showed correct,
  fully evidenced answers failing only on the label.
- CI installs the `index` extra for lint/type checks and the Linux and Windows
  tshark integration jobs.

#### Fixed

- Protocol-anomaly detection and the Modbus write check used space-separated
  display-filter sets, which tshark 4.x rejects, so both failed on every capture.

## 中文

4.0.0 是 3.1.0 之后的第一个发布版本。原先准备为 3.2.0 的内容没有单独发布，并入本版本，列在本说明的后半部分。

### 抓包索引引擎

路线图 4.0 的条目，先于长任务工作完成。全部位于可选的 `[index]` 扩展中；工具数仍为 54，`tools/list` 仍在 23,500 字节预算内。

- **抓包集合。** `wireshark_index(more_files=...)` 可以一次对多个抓包构建、查询、导出和查看状态。每个抓包保留自己的索引文件；查询时只读挂载并叠加，第一列为 `capture_id`，`captures` 表给出 id 对应的路径和 SHA-256。
- **时间线。** `action="timeline"` 列出主机、会话、协议、DNS 名称、TLS SNI、HTTP 主机、User-Agent 和 JA3/JA4 的首次与末次出现，带准确帧号、相对时间和 UTC 时间，可用显示过滤器限定时间窗。
- **Diff。** `action="diff"` 比较两个抓包，或同一抓包的两个过滤时间窗（`display_filter` 对比 `compare_filter`），只返回新增和消失的条目以及按类型的计数。
- **Parquet 导出。** `action="export"` 在索引目录下写出 `packets.parquet`、`flows.parquet` 和 `captures.parquet`，可加过滤器。
- **`wireshark_aggregate` 的 SQL 下推。** 当精确性门槛证明结果与流式累加器一致时，分组、去重计数、数值指标和时间桶在 DuckDB 中计算；否则照旧流式处理。`coverage.pushdown` 标明走了哪条路。
- **`wireshark_extract_fields` 走索引。** 由同一 tshark 构建的新鲜索引给出逐字节相同的输出；任何可能输出不同的情况都交给 tshark。
- **10 GB 基准档**加入 `scripts/benchmark_capture_index.py`，该脚本现在也测量时间线、diff、导出和 extract_fields。10 GB 抓包上索引在 0.08–1.1 秒内答出全部五个聚合问题；tshark 路径有四个因 stdout 上限失败，第五个用了 581 秒。1 GB 上索引快 408 倍（[结果](../docs/benchmarks/capture-index-2026-10-22.json)）。
- 查询连接改为内存中的 DuckDB 会话：先只读挂载各索引文件，再关闭外部访问并锁定配置。索引文件仍为 schema 版本 1，3.2 建好的索引继续有效。

### 同样包含在 4.0.0：证据优先的发现模型（原准备为 3.2.0）

#### 亮点

- **统一发现模型**：所有检测工具返回同一种有证据支撑的 `data.findings`，带稳定 id、
  可复核的原生 `tshark` 命令和候选 MITRE ATT&CK 技术。
- **调查案卷**：`wireshark_case` 把抓包、记录的工具结果、发现、分析者结论与备注保存在
  一份 JSON 记录中，Markdown 报告只依据这份记录生成。
- **可选的 DuckDB 抓包索引**：`pip install 'wireshark-mcp[index]'` 提供 `wireshark_index`；
  一次 tshark 解析后，后续 `wireshark_aggregate` 在 100 MB 上约快 21 倍、1 GB 上约快 27 倍，
  结果与 tshark 路径一致。
- **公开 Agent 评测结果**：用 Haiku 跑了两轮 180 格矩阵，轨迹由采集器写入。带 skill 的 MCP
  通过 73%，纯 MCP 65%，原生 tshark 57%；skill 的收益集中在安全类场景。见
  [Agent 评测结果](../docs/agent-evaluation-results_zh.md)。

#### 新增

- 统一发现模型：所有检测工具返回 `data.findings`，每条带稳定的内容哈希 `id`、
  产生它的 `tool`、`category`、可直接复核的原生 `tshark` 命令 `reproduce`，非 info
  级发现附候选 `mitre_attack` 技术。信标、外泄、协议异常、ARP 欺骗和 YARA 的结果从
  Markdown 或临时 JSON 改为该结构；`wireshark_quick_analysis` 的异常部分由其返回的
  发现渲染（`data.report` 加 `data.findings`）。
- `wireshark_case` 把调查保存为允许目录下的 JSON 案卷：抓包 SHA-256、记录的工具结果
  及其摘要/范围/覆盖、按 id 合并的发现、分析者结论与备注，以及只依据案卷生成的
  Markdown 报告；`wireshark://cases/{case_id}` 提供完整 JSON。见
  [发现模型与调查案卷](../docs/findings-and-cases_zh.md)。
- 可选的 DuckDB 抓包索引（`[index]` 扩展）。`wireshark_index` 一次 tshark 解析为抓包建立
  本地 DuckDB 索引（`action="build"`），查看是否新鲜（`status`），删除（`drop`），以及在
  `packets`、`pkt`、`flows` 表上执行一条只读、沙箱化的 `SELECT`（`query`）。见
  [抓包索引](../docs/capture-index_zh.md)。
- `wireshark_aggregate` 自动使用新鲜索引，并在 `coverage.source` 中标明来源（`"index"` 或
  `"tshark"`）。索引列保存 tshark 原始字段文本，因此索引答案与 tshark 路径一致；索引无法
  精确复现的过滤器、以及未索引的字段，会回退到 tshark，原因写在 `coverage.index_unused`。
- `scripts/benchmark_capture_index.py`，以及 100 MB 和 1 GB 合成抓包上的公开结果。
- `scripts/agent_eval_harness.py` 采集 180 格 Agent 矩阵：生成 9 个 `synthetic://`
  输入、写出盲测格、由自身执行 Agent 的每条查询（轨迹由采集器写入）、对每格调用任意
  命令行 Agent，并输出供 `check_agent_matrix.py` 使用的运行文件。见
  [Agent 评测](../docs/agent-evaluation_zh.md#用采集器运行矩阵)。
- 两轮 Haiku 的 [Agent 评测结果](../docs/agent-evaluation-results_zh.md)，门控输出见
  `docs/benchmarks/agent-matrix-2026-10-18-*.json`。

#### 变更

- `wireshark_detect_beaconing`、`wireshark_detect_exfiltration`、
  `wireshark_detect_protocol_anomalies`、`wireshark_detect_arp_spoofing`、
  `wireshark_yara_scan` 改为返回带 `findings`、`summary`、`scope`、`coverage` 的结果信封，
  不再是纯文本；`wireshark_quick_analysis` 返回 `data.report`，不再是裸字符串。
- 工具面共 54 个（analysis 42、core 34）：新增唯一保存状态的 `wireshark_case`，以及只写
  服务器自身索引缓存、标注为非破坏性的 `wireshark_index`。tools/list 前缀预算为 23,500 字节。
- Agent 评分只把场景接受的证据类型计入 `min_anchors`；其他类型可作为辅助证据，
  但仍按轨迹核对。此前任何额外的辅助证据都会导致判失败。
- 场景可列出 `acceptable_conclusions`。T15、T17、T18 在 `unresolved` 之外也接受
  `confirmed`，T17/T18 也接受能够确证该限制的查询覆盖度；三轮 Haiku 评测中，判断正确、
  证据齐全的回答只因标签而失败。
- CI 在 lint/类型检查以及 Linux、Windows tshark 集成任务中安装 `index` 扩展。

#### 修复

- 协议异常检测与 Modbus 写操作检查使用了以空格分隔的过滤器集合，tshark 4.x 会直接拒绝，
  导致两者在任何抓包上都失败。
